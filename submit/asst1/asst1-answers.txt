common/libc contains basic C functions
userland/lib/libc contains user-space functions

The libc functions are split into two locations because:
- common/libc contains generic C functions that do not depend on system calls. For example, string functions like strlen (common/libc/string/strlen.c) or memory functions like memcpy are useful in both the kernel and userland. The kernel cannot rely on user-space syscalls, so it needs its own copy of these utilities.
- userland/lib/libc contains the user-level C library that interacts with the kernel. For example, write (userland/lib/libc/syscalls/write.c and syscalls-mips.S) or putchar (userland/lib/libc/stdio/putchar.c) eventually execute the syscall instruction to trap into the kernel. These functions are only relevant for user programs.
This separation allows code reuse of generic helpers while keeping system-call related code isolated to userland.
